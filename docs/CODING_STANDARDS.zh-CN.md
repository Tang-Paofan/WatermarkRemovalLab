# 编码规范

[English](CODING_STANDARDS.md) | [简体中文](CODING_STANDARDS.zh-CN.md)

本规范适用于 Watermark Removal Lab 的生产代码、测试、脚本、基准、API、CLI 命令和桌面端适配器。它在实现开始前定义稳定的项目规则；后续可以增加具体工具配置，但不得降低这些要求。

## 1. 语言与格式

- 源码标识符、类型名、代码注释、文档字符串、日志字段、CLI 参数、API 字段和机器可读消息使用英语。
- 面向用户的文字可以本地化，但不同语言必须保存在独立文件或资源目录中。
- 统一使用 UTF-8、LF 换行、文件末尾换行，并移除行尾空格。
- Python 使用四个空格缩进，最大行宽为 100 个字符。
- 仅格式调整不得与行为变更混在同一个提交中。
- 仓库加入自动格式化、静态检查和类型检查配置后，以对应配置为准。

## 2. 架构与依赖方向

系统遵循：

```text
CLI / 桌面端 / API 适配器
            ↓
应用流水线
            ↓
检测器 / 分割器 / 掩膜细化器 / 补全器 / 质量评估器
            ↓
图片、掩膜、视频、模型和运行时工具
```

规则：

- 核心层和流水线模块不得导入 CLI、桌面端、Web 或 GUI 模块。
- 核心接口中不得出现 UI 框架类型。
- 算法实现不得解析命令行参数或渲染界面。
- 文件 IO、模型推理、掩膜处理、评测和展示必须保持职责分离。
- 定位与补全必须可以独立替换。
- 在至少两个真实实现确实需要之前，不建立 registry 或插件抽象。
- 避免全局可变状态；模型缓存和运行 provider 必须具有明确的所有者和生命周期。

## 3. 公共接口

- 公共函数、类、协议、数据类和不直观的数组变换必须添加类型标注。
- 优先使用小型不可变请求/结果对象，避免过长参数列表。
- Python 边界中的路径统一使用 `pathlib.Path`。
- 公共行为必须说明接受的形状、数据类型、颜色空间、坐标系统、单位和失败方式。
- 字段含义不同的数据不得通过无结构元组返回。
- 首次公开发布后，破坏兼容性的变更必须具有架构决策记录或明确迁移方案。

## 4. 图片与掩膜不变量

除非适配器明确说明，否则：

- 图片为 `uint8`、`H × W × 3`、RGB；
- Alpha 独立保存为 `uint8`、`H × W`；
- 二值掩膜为 `bool`、`H × W`；
- 序列化掩膜使用 0 表示背景、255 表示选中像素；
- 边界框使用 `(x_min, y_min, x_max, y_max)`，左上坐标包含、右下坐标不包含；
- 数组坐标为 `(row, column)`，面向用户的点为 `(x, y)`；
- 处理前掩膜与图片的空间尺寸必须一致；
- 不得修改原始输入对象；
- 输出编码之前，只允许最终细化掩膜内的像素发生变化；
- 除非未来操作明确声明编辑 Alpha，否则原始 Alpha 必须保持不变。

颜色转换必须发生在适配器边界。OpenCV 代码显式转换 RGB/BGR；模型适配器显式说明归一化方式和张量布局。

JPEG 等有损格式可能在编码时改变像素。像素一致性测试必须比较内存结果或无损输出，并区分算法变更与编码器变更。

## 5. 掩膜处理

- 每个掩膜变换都应返回新掩膜，或明确说明受控的原地修改。
- 膨胀、腐蚀、羽化、阈值和 padding 必须使用明确单位与参数。
- 除非操作明确要求存在选中像素，否则空掩膜是合法输入。
- 必须定义全图掩膜、接触边界的掩膜和越界提示的处理方式。
- 流水线必须记录或能够复现实际用于补全的最终掩膜。
- 掩膜细化不得静默扩张到配置范围之外。

## 6. 错误、日志与可观测性

- 在适配器边界校验用户输入，在核心层校验领域不变量。
- 抛出具体领域异常并提供可操作消息；不得使用裸 `except`。
- 转换后端异常时保留原始异常。
- 核心模块使用结构化日志，不直接 `print`。
- CLI 适配器负责终端输出和退出码映射。
- 日志不得包含凭据、可避免的完整私有路径或嵌入的用户媒体。
- 长任务必须暴露进度和取消边界，且不得依赖具体 UI 框架。

## 7. 依赖与模型

- 只有标准库和现有依赖无法合理满足需求时才增加新依赖。
- 区分运行时、开发、可选模型和平台专用依赖。
- 引入 Python 包骨架后，使用仓库认可的工具固定或锁定环境。
- 重型可选依赖应延迟导入；缺失时给出清晰的安装处理方式。
- 模型下载必须由用户明确触发，并记录缓存位置、来源 URL、预期许可证和完整性校验。
- 不得提交模型权重、数据集、生成输出、密钥或本地缓存。
- 代码许可证、模型权重许可证和数据集许可证必须分别审计。
- 分发第三方产物前更新 [MODEL_LICENSES.md](../MODEL_LICENSES.md) 和 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

## 8. 测试

每个行为变更都必须提供与风险相称的测试。

- 单元测试覆盖坐标转换、掩膜操作、校验和纯变换。
- 集成测试覆盖 IO、推理适配器、流水线、CLI 行为和 provider 选择。
- 回归测试使用最小且安全的样例复现已修复缺陷。
- 质量测试使用合成或已授权数据集，并记录指标定义。
- 测试必须确定性执行，或说明容差和非确定性来源。
- CPU-only 测试是必需基线；GPU/模型测试必须单独标记。
- 默认单元测试禁止网络访问和模型下载。
- 临时输出使用隔离测试目录，并由测试框架清理。

关键基线断言包括：

- 最终掩膜尺寸与图片一致；
- 有损编码前，最终掩膜外像素完全一致；
- Alpha 保持不变；
- 输入数组和文件没有被修改；
- 无效坐标和尺寸不匹配能够清晰失败；
- CLI 失败返回非零退出码，且不留下不完整的最终输出。

## 9. 评测与基准

- 基准必须说明硬件、操作系统、运行 provider、模型版本/哈希、输入尺寸、预热策略、样本数和聚合方法。
- 质量指标定义必须说明掩膜、裁剪策略、颜色空间、分母和重要排除项。
- OpenCV 基线与模型方案必须使用相同输入和掩膜条件比较。
- 不得把逐帧视频补全描述为具备时序一致性。
- 性能优化必须保持质量与正确性检查，或说明有意接受的权衡。
- 除非是小型且经过评审的参考产物，否则不提交生成的基准结果。

## 10. CLI、API 与桌面端适配器

- CLI 是第一个产品适配器，必须调用公共应用服务，不得直接依赖后端私有细节。
- CLI 必须可被脚本调用：退出码稳定、覆盖行为明确，并支持可选机器可读输出。
- 桌面应用复用相同的请求/结果契约、进度事件、取消机制和模型缓存。
- Qt、Electron 或其他 UI 选择不得改变核心流水线。
- API 和桌面 worker 不得重新实现一套算法逻辑。

## 11. 文档与负责任使用

- 公开功能必须提供文档、限制说明以及至少一个已授权或合成示例。
- 英文和简体中文文档必须分文件维护；同时存在时保持结构一致。
- 模型/provider 名称和能力必须准确表述。
- 实验性和规划功能不得描述为生产就绪。
- 示例不得包含许可不明的版权媒体，也不得针对付费预览水印服务。
- 许可证和负责任使用声明是产品要求，不是可选宣传文字。

## 12. 完成定义

只有满足以下条件，变更才算完成：

- 预期行为和非目标清晰；
- 架构和数据不变量仍然成立；
- 测试与静态检查通过；
- 适用的文档和译文已更新；
- 适用的模型与第三方许可证已登记；
- 不包含生成产物、凭据、无关变更或大型二进制文件；
- 提交信息符合 [CONTRIBUTING.zh-CN.md](../CONTRIBUTING.zh-CN.md)。
