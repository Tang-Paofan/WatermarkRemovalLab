## 验收结论

M1 及其 B1 顺序图片批处理切片在既定工程范围内通过验收。该基线可以作为 M2 的质量对照
和兼容性边界。

本结论确认无模型图片核心、单图 CLI、顺序批次契约、状态持久化、取消边界和已记录的退出
行为符合要求；它不表示 OpenCV Telea 或 Navier-Stokes 已达到模型级修复质量。

## CLI 人工验收场景

以下场景均通过安装后的 `wrl` 命令执行，没有直接调用 OpenCV 或批处理私有函数。

| 场景 | 观察到的终态计数 | 退出码 | 结果 |
|---|---:|---:|---|
| 递归目录、共享 box、NS、PNG 映射、自定义 JSONL | 2 项成功 | `0` | 通过 |
| 镜像掩膜目录缺少一个掩膜 | 1 项成功、1 项失败 | `3` | 通过 |
| Manifest 逐项覆盖方法与选项 | 2 项成功 | `0` | 通过 |
| Manifest 首项无效后的 fail-fast | 1 项失败、1 项取消 | `3` | 通过 |
| 已有输出使用 `error` | 预检拒绝 | `2` | 通过 |
| 已有输出使用 `skip` | 2 项跳过 | `0` | 通过 |

部分失败场景记录了 `mask_not_found`，且没有发布失败项输出。fail-fast 场景为首项记录
`input_not_found`，为未调度项记录 `fail_fast`，两个输出都没有发布。

CLI 将 Ctrl+C 映射为 `user_cancelled` 和退出码 `130`，以及将致命编排错误映射为退出码
`4`，均由端到端 CLI 测试覆盖。人工终端会话没有合成操作系统 Ctrl+C 事件，因为强制终止
子进程无法验证协作式取消契约。

## 状态与完整性观察

- 目录发现与结果顺序遵循确定性的相对路径顺序。
- `run.json`、每条 `results.jsonl` 记录和 `summary.json` 均可解析为有效 JSON。
- `run.json` 将 `worker_count` 记录为 1，并保留归一化、可移植的请求。

- 成功、失败、跳过和取消终态都有对应结果记录。
- 汇总计数与聚合分母包含每个已发现项目。
- 成功或失败场景结束后均没有残留 `.tmp` 文件。

- 失败和取消项没有留下最终媒体输出。
- 验收产物位于被忽略的 `tmp/` 下，因此 Git 工作区保持干净。

## 已接受的限制

- 定位要求用户提供 box 或掩膜。
- Telea 和 Navier-Stokes 是透明的工程基线，不是语义修复模型。
- 大矩形掩膜可能留下明显接缝或色带，Telea 尤其明显。
- 结构、纹理或语义复杂背景可能产生明显伪影。
- B1 固定使用一个 worker，不支持重试或恢复。
- JPEG 输出有损且不能保留 Alpha。

这些限制属于预期的 M1 行为，不重新归类为缺陷。M2 必须保留 OpenCV 基线，并在相同掩膜
和输入条件下评估 LaMa 是否改善质量。

## 进入 M2 的条件

M1 验收通过并不直接授权使用某个模型产物。开始 M2 实现前必须：

1. 选择精确的 LaMa 代码与权重产物；
2. 分别核验代码、权重和训练数据条款；
3. 在 `MODEL_LICENSES.md` 中记录来源、版本、再分发条款和完整性哈希；
4. 在 `THIRD_PARTY_NOTICES.md` 中记录复制代码、二进制文件和通知要求；
5. 定义带 padding 的局部裁剪与仅掩膜回贴契约；
6. 定义 CPU/GPU provider、模型缓存、离线测试和基准评测边界。
