# ADR 0001：CLI 优先、核心层与界面无关

[English](0001-cli-first-core.md) | [简体中文](0001-cli-first-core.zh-CN.md)

- 状态：已接受
- 日期：2026-07-23

## 背景

Watermark Removal Lab 需要支持基于 OpenCV、SAM/SAM 2、LaMa、ONNX Runtime 和 FFmpeg 的图片与视频实验。第一个可用界面将是 CLI；CLI 证明流水线可行后可以开发桌面应用，但 Qt、Electron 或其他 UI 框架的选择有意推迟。

如果算法代码与第一个界面耦合，后续桌面端、API 和评测将重复实现行为，也难以比较正确性。

## 决策

项目将在任何桌面应用之前，构建无界面且与 UI 框架无关的 Python 核心。

- CLI 是第一个适配器，调用公共应用服务。
- 流水线和算法组件不得导入 CLI、桌面端、Web 或 GUI 模块。
- 请求、结果、进度事件、取消和错误使用与框架无关的契约。
- 图片和视频处理行为只在核心层实现一次。
- 未来的 Qt 桌面应用可以直接调用 Python 服务。
- 未来的 Electron 应用可以通过本地 worker 或 API 边界调用相同服务。
- 只有在 CLI 和早期原型证明交互需求及打包约束之后，才选择桌面框架。

## 初始边界

```text
CLI
 ↓
应用服务
 ↓
图片流水线
 ↓
掩膜工具 + OpenCV 补全器
```

SAM/SAM 2、LaMa、自动检测器、Web API 和视频处理将在未来扩展此边界，但不改变依赖方向。

## 影响

正面影响：

- 算法行为可以独立测试；
- CLI、桌面端、API 和基准可以共享同一实现；
- Qt 与 Electron 的选择仍然属于产品和分发决策；
- 模型缓存、进度、取消和评测可以使用公共契约。

成本：

- 必须显式设计适配器边界和数据契约；
- 首个 CLI 不能通过调用后端私有细节走捷径；
- GUI 专用图片与事件类型必须在桌面端边界转换。

## 重新评估条件

只有经过验证的需求无法在不引入框架专用核心依赖的情况下表达时，才重新评估本决策。单纯为了方便不足以推翻本决策。
