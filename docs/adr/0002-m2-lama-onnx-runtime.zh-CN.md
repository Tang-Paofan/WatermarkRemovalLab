# ADR 0002：M2 使用固定版本的 LaMa ONNX Runtime

[English](0002-m2-lama-onnx-runtime.md) |
[简体中文](0002-m2-lama-onnx-runtime.zh-CN.md)

- 状态：接受用于非捆绑研究集成
- 日期：2026-07-24

## 背景

M1 已把 OpenCV Telea 与 Navier-Stokes 建立为无模型基线。M2 需要加入明显更强的补全后端，同时不能让 PyTorch、模型下载或 GPU 运行时成为核心包的必需条件。

初始候选是 `Carve/LaMa-ONNX` 的 `lama_fp32.onnx`。模型卡将其描述为 `big-lama` 的推荐 opset-17 导出版本，空间输入固定为 512×512。Hugging Face 提供了准确产物大小和 SHA-256。

审查也发现了限制：

- 导出笔记本没有固定导出器 Git 版本；
- 没有记录源 `big-lama.zip` 的 SHA-256；
- 模型卡声明 Apache-2.0，但 Places2 官方图片下载条款把训练数据限制为非商业研究和教育用途；
- 本地学习平台的实现不需要再分发该权重。

当前维护者工作站无法承载真实模型运行时。该限制不得让托管 API 提前进入 M2，也不得让默认开发依赖付费 GPU。独立算力主机可以在不改变应用边界的情况下运行同一个无界面 CLI。

## 决策

M2 首先通过 ONNX Runtime 集成一个固定版本的 LaMa ONNX FP32 产物。

- 准确描述符、产物提交、字节大小和 SHA-256 记录在
  [MODEL_LICENSES.md](../../MODEL_LICENSES.md)。
- 模型保持可选，永不提交或捆绑，只能由用户明确触发安装。
- 安装器在下载前展示声明的模型许可证和数据集限制提示。
- 处理流程不会下载缺失模型。
- M2 加载器只接受已审查的产物哈希。
- CPU 与 CUDA ONNX Runtime 发行包属于不同的可选依赖组。
- CPU 是默认 provider；请求 CUDA 而 CUDA provider 未注册时直接失败。
- 使用确定性的带 padding 正方形裁剪适配固定 512×512 模型输入。
- 只把原始分辨率最终掩膜选中的像素回贴到结果。
- 模型与运行时会话具有显式应用层所有者和有界缓存。
- 未安装模型依赖时 OpenCV 仍完全可用。
- 本地工作站与普通 CI 保持无模型；AutoDL 是真实模型与 CUDA 验收的初始参考主机。
- AutoDL 可以被其他兼容 Linux 主机替代，不得导入、调用或出现在核心契约中。
- CLI、模型与已授权媒体一起在算力主机运行。M2 不增加工作站到算力主机的上传或推理 API。

该产物获准用于非捆绑研究集成与算力主机本地评测。本决策不批准再分发权重，也不对商业用途作出判断。这些行为需要重新审查。

## 后果

正面影响：

- M2 可以在不引入原始 PyTorch 训练栈的情况下验证 LaMa；
- 固定提交与 SHA-256 让用户下载可以复现并能发现篡改；
- 可选运行时依赖组保持 OpenCV 基线轻量；
- 裁剪与 provider 契约可由 CLI、批处理、桌面端和后续 API 复用；
- 固定产物让基准与 B2 恢复指纹可比较。
- 贡献者可以在 AutoDL 或其他兼容主机复现验收，而无需改变核心架构。

成本与限制：

- 每个裁剪都需要进入并离开固定 512×512 空间；
- 大掩膜缩小时可能损失细节；
- CPU 与 CUDA 打包需要分别验证；
- 当前无法从完整固定版本的源链重现转换；
- 模型许可证元数据与训练数据条款都必须持续可见；
- 本决策不允许发布包捆绑该权重。
- 默认验证与真实模型验证来自两个已声明环境，必须通过准确仓库提交和证据记录关联。

## 已考虑的替代方案

### 首先集成原始 PyTorch LaMa

M2 暂不采用，因为它会在 CLI 模型边界、裁剪行为和基准得到验证前引入更大的依赖与运行时表面。它仍可作为后续对比选项。

### 在本仓库重新导出模型

暂缓。可信的派生产物需要固定原始 checkpoint、导出器代码、工具链、转换过程、等价性测试，以及新的产物哈希和许可证记录。M2 不需要发布转换后的权重。

### 接受任意 ONNX 路径

M2 不采用，因为名称、形状、归一化、输出范围、许可证与完整性都将失去边界。未来可以通过描述符格式支持其他已审查产物。

### 捆绑已审查 ONNX 文件

不采用，因为仓库应保持小巧，而且本次审查没有批准再分发及其训练数据影响。

## 重新审查条件

以下情况需要重新审查：

- 上游发布提供更完整的固定版本来源链；
- 其他已审查产物显著改善质量或运行时行为；
- 动态空间形状或切片成为已接受需求；
- 提议模型再分发、商业打包或托管服务；
- ONNX Runtime provider 打包方式发生实质变化；
- 基准证明固定形状变换不适合目标图片。
