# 批量处理设计

[English](BATCH_PROCESSING.md) | [简体中文](BATCH_PROCESSING.zh-CN.md)

本文档把批量处理定义为贯穿图片和视频里程碑的可复用编排能力，并补充[工程路线图](ROADMAP.zh-CN.md)与 [M1 规范](milestones/M1-opencv-image-baseline.zh-CN.md)。

## 1. 设计目标

批量处理必须：

- 调用 CLI、桌面端和 API 共用的单项应用服务；
- 支持确定性的目录发现和版本化清单输入；
- 在高成本工作开始前校验完整计划；
- 隔离逐项失败并保留已完成输出；
- 生成增量机器可读结果和最终汇总；
- 支持安全取消，并在 B1 之后支持经过校验的恢复；
- 在显式限制内调度 CPU、GPU、模型缓存和视频资源；
- 暴露可供未来桌面端和服务队列复用的稳定契约。

## 2. 非目标

批量层不负责：

- 实现检测、分割、掩膜细化、补全、编码或评测算法；
- 在项未提供已认可定位来源时静默推断边界框或掩膜；
- 覆盖输入；
- 仅根据输出存在就判断某项已完成；
- 重试确定性的校验失败或不支持内容；
- 在聚合指标中隐藏失败、跳过或取消项；
- 在 B1 或 B2 引入分布式执行；
- 在图片与视频单项流水线稳定前支持混合媒体清单。

## 3. 架构

```text
目录 / 清单 / API / 桌面端适配器
                    ↓
              批次规划器
                    ↓
          已校验不可变 BatchPlan
                    ↓
        资源感知批次编排器
                    ↓
            单项应用服务
                    ↓
        现有图片或视频流水线
```

批次规划器解析默认值、路径、输出映射和冲突。编排器控制项生命周期、资源、取消、结果和汇总。只有单项服务可以访问算法流水线。

## 4. 核心契约

未来 Python API 应使用与框架无关的等价结构表达：

```text
BatchSpec
  schema_version
  operation
  defaults
  items
  overwrite_policy
  failure_policy
  execution_policy

BatchItem
  index
  id
  media_type
  input
  output
  localization
  options

BatchPlan
  run_id
  normalized_spec
  validated_items
  required_resources
  warnings

ItemResult
  schema_version
  run_id
  item_index
  item_id
  status
  normalized_request
  fingerprints
  output
  metrics
  warnings
  error
  timing

BatchSummary
  run_id
  discovered
  validated
  succeeded
  skipped
  failed
  cancelled
  aggregate_metrics
  result_file
```

请求和结果不得包含 Qt、Electron、HTTP、终端或其他框架专用对象。

## 5. 输入模式

### 目录适配器

目录模式是便捷适配器，其职责为：

1. 发现受支持文件；
2. 归一化相对路径；
3. 按确定顺序排序；
4. 配对共享边界框或镜像掩膜；
5. 映射输出路径；
6. 生成普通批次项。

目录适配器不得自行执行处理。

规则：

- 默认不递归；
- 只有显式指定时才递归；
- 忽略隐藏的批次状态目录；
- 默认拒绝位于输入根目录内的输出根目录；
- 在不区分大小写的文件系统上检查冲突时进行大小写归一化；
- 路径包含性检查前解析符号链接；
- 除非未来策略明确允许，否则不得跟随指向声明输入根目录之外的符号链接。

### 清单适配器

标准清单使用版本化 JSON Lines。第一条记录描述批次与默认值，后续记录描述各项。

```json
{"record":"batch","schema_version":1,"media":"image","operation":"remove","defaults":{"method":"telea","radius":3,"dilate":1}}
{"record":"item","id":"corner-a","input":"inputs/a.png","output":"a.png","box":[20,20,160,48]}
{"record":"item","id":"corner-b","input":"inputs/b.png","output":"b.png","mask":"masks/b.png","method":"ns"}
```

清单 v1 规则：

- 第一条且只有一条 `batch` 记录；
- 后续每条记录都是 `item`；
- 项 ID 是唯一非空字符串；
- 序列化路径使用正斜杠；
- 输入和掩膜路径相对于清单目录；
- 输出路径相对于声明的输出根目录；
- 每个图片去除项必须且只能具有一种定位来源；
- CLI 覆盖只作用于批次默认值，不得静默替换显式项字段；
- 未知 schema 版本和未知必需字段在预检阶段失败；
- 重复的标准化输出路径在预检阶段失败；
- 越过声明根目录的路径遍历在预检阶段失败。

未来清单版本可以增加视频或混合媒体，但不得改变 v1 行为。

## 6. 批量定位

批量定位来源可以是：

- 对每张图片分别校验的共享边界框；
- 逐项边界框；
- 镜像掩膜目录；
- 逐项掩膜；
- 未来经过评审的检测器配置或已保存提示集合。

规则：

- 面向用户的清单坐标保持 `x,y,width,height`；
- 图片方向归一化之后再校验掩膜尺寸；
- 共享边界框可以在较小图片上失败，但不使其他项无效；
- 引入自动定位后，记录检测器名称、版本、置信度和建议来源；
- 交互提示只有保存为显式项数据后才能用于批量处理。

## 7. 规划与预检

第一项运行前必须完成规划。

预检项目：

- 清单/schema 有效性；
- 项 ID 唯一性；
- 受支持媒体与操作；
- 输入和辅助文件存在性；
- 路径包含性与符号链接策略；
- 输出路径唯一性；
- 输入输出不别名；
- 覆盖策略冲突；
- 必需定位字段；
- 选项类型与范围；
- 可以低成本检查时的后端/provider 可用性；
- 估计资源类别和不支持组合。

预检生成不可变 `BatchPlan`。必须解码后才能确定的逐项尺寸仍可能在项校验时失败，并必须记录为逐项失败。

## 8. 输出映射与原子性

输出根目录保存用户输出，批次状态隔离到：

```text
OUTPUT_ROOT/
├── <映射后的用户输出>
└── .wrl-batch/
    └── RUN_ID/
        ├── run.json
        ├── results.jsonl
        └── summary.json
```

规则：

- 执行前已知全部最终输出路径；
- 临时文件创建在最终目标旁边；
- 单项服务验证并原子提交每个输出；
- 失败项不留下最终输出；
- 现有输出遵循 `error`、`skip` 或 `replace`；
- `error` 冲突在预检阶段发现；
- 目录发现时，状态文件不得被视为输入媒体；
- 批次元数据包含路径和指标，不包含媒体像素。

## 9. 项生命周期

每项遵循：

```text
discovered
    → validated
    → queued
    → running
    → succeeded | skipped | failed | cancelled
```

B1 之后，恢复过程可以在重新排队前把以前成功的项判断为 `stale`。

同一次运行中的终止状态不可变。重试是在相同项结果历史下记录的新 attempt，不得静默重写状态。

## 10. 失败策略

默认行为是 `continue`：

- 记录逐项校验或处理失败；
- 其他有效项继续；
- 最终进程退出码表示部分失败。

可选 `fail-fast` 行为：

- 首次失败后停止调度新项；
- 允许正在进行的原子步骤安全结束；
- 保留成功输出；
- 在汇总中把未调度项标记为未开始或取消。

无法读取的清单、无效输出根目录、损坏状态存储或无法提交结果记录属于批次致命失败，并停止运行。

## 11. 结果与可观测性

运行过程中 `results.jsonl` 只能追加。每条记录包含：

- schema 与运行版本；
- 项索引和 ID；
- attempt 编号；
- 归一化输入/输出引用；
- 状态；
- 归一化流水线配置；
- 可用时的输入、辅助数据、配置、模型和软件指纹；
- 输出引用与可选完整性哈希；
- 耗时与资源指标；
- 警告；
- 稳定错误代码、面向用户的消息和后端类别。

堆栈跟踪写入调试日志，不进入标准结果记录。

结束时原子写入 `summary.json`，包含所有终止状态数量。聚合指标必须包含分母，不得在不说明的情况下排除失败项。

## 12. 退出行为

CLI 退出码遵循当前里程碑规范：

- 只有全部适用项成功或被有意跳过时才返回成功；
- 一个或多个项失败时使用独立的部分失败码；
- 预检/配置使用独立错误码；
- 编排/IO 致命失败使用独立错误码；
- 用户取消使用 130。

API 和桌面端适配器把相同批次汇总映射为各自传输状态，不改变项语义。

## 13. 取消与崩溃安全

- 取消使用与框架无关的共享 token。
- 观察到取消后停止新工作。
- 活动项只在后端定义的安全边界停止。
- 已完成输出和已刷新结果记录保持有效。
- 在安全情况下清理临时输出。
- 每个终止项结果后刷新批次状态。
- 进程崩溃不得使部分写入媒体表现为最终文件。

B4 视频任务定义额外帧/时间检查点，但不降低最终输出原子性。

## 14. 恢复设计

经过校验的恢复从 B2 开始。`--resume` 绝不表示“输出存在就跳过”。

只有以下身份全部匹配，才能复用某项：

- 项 ID 和归一化输出映射；
- 输入内容指纹；
- 掩膜、提示、模板或辅助内容指纹；
- 归一化流水线配置哈希；
- 应用/流水线版本；
- 适用时的具体模型产物哈希；
- 以前记录的成功状态；
- 预期输出存在且通过配置的完整性检查。

任何身份不同都会把项标记为 `stale`，必须重新处理或由策略显式拒绝。

内容哈希使用适合完整性验证的密码学哈希。发版 MD5 要求独立存在，不替代运行时完整性指纹。

## 15. 重试设计

B1 禁用自动重试。

后续有界重试只适用于被分类为临时的失败，例如：

- provider 暂时不可用；
- 可重试服务传输失败；
- 降低并发后的临时资源不足。

不得自动重试：

- 无效边界框、掩膜、清单或路径；
- 不支持格式或 provider；
- 确定性解码失败；
- 许可证或模型完整性失败；
- `error` 策略下的输出冲突；
- 输入或配置不变时必然重复的失败。

每次 attempt 都记录原因和延迟。

## 16. 并发与资源调度

B1 使用一个 worker。

B2 引入显式资源感知并发：

- CPU worker 受配置和内存预算限制；
- GPU 推理默认每个设备一个活动 worker，除非后端证明并行安全；
- 模型 session 和 embedding 只通过声明为线程安全的缓存共享；
- 队列深度有界；
- 可能时，项在调度前声明资源类别；
- 内存压力可以暂停调度，但不得静默改变质量设置；
- 只有保持排序和取消正确时，输出编码才可以使用独立有界池。

并发下结果记录可以按完成顺序写入，但每条结果都包含原始项索引，最终汇总按项索引标准化。

## 17. 评测聚合

B3 批量评测报告：

- 发现、有效、成功、失败、跳过和取消总数；
- 各流水线数量；
- 指标分母和缺失值数量；
- 延迟分布，而不只是平均值；
- 批次峰值 RAM/VRAM 与配置并发；
- 可审计的逐项原始指标。

失败项不得获得虚构质量分数。跨流水线比较使用匹配的成功项集合，或明确报告不同分母。

## 18. CLI、API 与桌面端复用

无界面应用层最终应暴露类似接口：

```text
plan_batch(spec) -> BatchPlan
run_batch(plan, progress_sink, cancellation_token) -> BatchSummary
resume_batch(state, policy, progress_sink, cancellation_token) -> BatchSummary
```

适配器负责：

- CLI 解析和终端展示；
- HTTP 序列化与认证；
- 桌面端对话框、表格和进度视图。

适配器不负责：

- 项状态迁移；
- 资源调度；
- 重试或恢复决策；
- 输出原子性；
- 聚合指标计算。

## 19. 安全与隐私

- 拒绝路径遍历和标准化输出冲突。
- API 清单不得暴露任意服务器本地路径。
- 不记录媒体内容或凭据。
- 可使用相对引用时，不在可移植结果文件中记录完整私有路径。
- 服务环境限制清单大小、项数、队列深度、输出大小、时间、RAM 和 VRAM。
- 未来如果支持压缩包，解压前必须校验。
- 未经显式功能和同意，不得把用户媒体发送到远程服务。

## 20. 交付阶段

### B1 对应 M1

- 仅顺序执行；
- 目录与清单适配器；
- 预检、原子输出、增量结果、汇总、快速失败和取消；
- 不支持恢复或重试。

### B2 对应 M2–M4

- 经过校验的恢复；
- 有界资源感知并发；
- 模型/session/embedding 缓存复用；
- 临时失败重试分类；
- 检测器与已保存提示项数据。

### B3 对应 M5–M6

- 评测聚合；
- 异步任务队列；
- 状态、超时、配额与服务安全路径契约；
- 桌面端/API 复用。

### B4 对应 M7–M8

- 视频检查点；
- 时长感知调度；
- 长任务安全重启；
- 单项流水线达到退出门槛后才支持混合媒体。

## 21. 验收原则

只有满足以下条件，一个批量阶段才算完成：

- 复用公共单项服务；
- 规划确定且经过校验；
- 输出映射无冲突且永不覆盖输入；
- 逐项失败保持可见；
- 最终输出原子化；
- 取消保留已完成工作且不发布部分文件；
- 机器可读结果能够还原发生的行为；
- 当前阶段资源使用有界；
- 测试覆盖当前阶段引入的部分失败与恢复行为。
