# M2 规范：LaMa 图片补全

[English](M2-lama-image-inpainting.md) | [简体中文](M2-lama-image-inpainting.zh-CN.md)

本文档是 M2 的实现与验收契约。它在保持 M1 图片、掩膜、输出安全和适配器边界的前提下，增加一个可选的 LaMa ONNX 补全器。

初始模型产物已获得“非捆绑研究集成”的条件准入。该准入不包括模型再分发，也不对商业用途作出结论。详见
[MODEL_LICENSES.md](../../MODEL_LICENSES.md) 和
[ADR 0002](../adr/0002-m2-lama-onnx-runtime.zh-CN.md)。本地/AutoDL 验证拆分和可移植复现步骤记录在
[模型执行指南](../MODEL_EXECUTION.zh-CN.md)。

## 1. 目标

M2 必须：

- 在 M1 的同一个公开单图应用服务后增加基于模型的补全器；
- 从最终细化掩膜推导带 padding 的局部裁剪；
- 以确定性方式把裁剪适配到已审查的固定形状 LaMa ONNX 契约；
- 只在原始分辨率最终掩膜为真的位置回贴生成像素；
- 保持输入不可变、Alpha、原子输出和覆盖策略；
- 显式选择 CPU 与 CUDA provider，并报告实际使用的 provider；
- 在 Git 之外安装和缓存模型产物，并强制校验 SHA-256；
- 在不安装模型依赖时继续提供 OpenCV Telea 与 Navier-Stokes；
- 在不安装或运行真实模型时仍能完成普通本地开发；
- 在可复现的合成或已授权输入上比较 LaMa 与 M1 基线；
- 引入 M2 对应的 B2 能力：已验证恢复与 provider 感知的有界调度。

## 2. 非目标

M2 不包括：

- 自动水印检测；
- SAM/SAM 2 提示或分割；
- 任意第三方 LaMa 文件或通用模型注册表；
- 在常规应用内训练、微调或转换 LaMa 权重；
- 切片推理，或宣称 ONNX 原生支持任意分辨率；
- 远程推理、工作站到 AutoDL 的上传 API 或其他托管模型服务；
- 桌面端、Web 或 API 适配器；
- 视频处理或时序一致性；
- 声称 LaMa 对所有图片都自动优于传统算法；
- 把模型权重打包进仓库、wheel、源码包或发布资产；
- 在上游证据不完整时批准模型权重再分发或商业使用。

## 3. 架构切片

```text
CLI / B2 批量适配器
          ↓
单图去除服务
          ↓
最终掩膜 + 局部裁剪规划器
          ↓
补全器接口 ─────────────────────────┐
    ↓                               ↓
OpenCV 适配器              LaMa ONNX 适配器
                                    ↓
                         模型存储 + 会话所有者
                                    ↓
                         ONNX Runtime provider
          ↓
原始分辨率仅掩膜回贴
          ↓
原子输出
```

LaMa 适配器不得执行文件发现、输出编码、CLI 渲染、批次状态迁移或网络下载。模型存储负责安装和完整性校验。应用服务负责会话生命周期，并向适配器传入已经验证的模型路径。

### 执行环境拆分

当前维护者工作站不作为真实模型执行环境。这是环境约束，不是核心架构依赖。

- 本地工作站和普通 CI 运行全部默认离线测试、OpenCV 集成、裁剪变换测试、CLI 测试和假 ONNX 会话测试。
- AutoDL 是固定模型、CPU 真实模型冒烟、CUDA provider 测试与资源基准的初始参考主机。
- 任何兼容 Linux 主机都可以替代 AutoDL，前提是使用相同 Git 提交、锁文件、模型 SHA-256、规范化配置与证据字段。
- 项目 CLI 在算力主机上与模型和已授权媒体一起运行。M2 不会把 AutoDL 变成推理服务器。

完整步骤见 [MODEL_EXECUTION.zh-CN.md](../MODEL_EXECUTION.zh-CN.md)。

## 4. 保持不变的数据契约

M1 不变量继续强制生效：

- 解码图片：`uint8`、`H × W × 3`、RGB；
- 可选 Alpha：独立 `uint8`、`H × W`；
- 最终掩膜：`bool`、`H × W`；
- 边界框：`(x_min, y_min, x_max, y_max)`，不包含右下坐标；
- 序列化掩膜：0 表示背景，255 表示选中；
- 永不修改输入；
- 除非未来操作明确编辑 Alpha，否则 Alpha 必须逐字节保持一致；
- 有损编码前，原始分辨率最终掩膜外像素必须完全不变。

裁剪规划器与模型适配器返回新数组。模型 padding、缩放和模型空间掩膜外生成的像素都不得扩大最终回贴区域。

## 5. 初始审查产物

首个实现只面向一个具体产物：

| 字段 | 必需值 |
|---|---|
| 后端 ID | `lama-onnx-fp32` |
| 仓库 | `Carve/LaMa-ONNX` |
| 产物 | `lama_fp32.onnx` |
| 产物提交 | `a3ee2fca54baebec351b8fa7786154ffa7555aa6` |
| 模型卡提交 | `c3c0c9e468934d62e79c329e35d82dd09ff8c444` |
| 大小 | `208044816` 字节 |
| SHA-256 | `1faef5301d78db7dda502fe59966957ec4b79dd64e16f03ed96913c7a4eb68d6` |
| ONNX opset | 17 |
| 空间形状 | 固定 `512 × 512` |

模型卡把该文件标为原始 PyTorch `big-lama` 模型的推荐导出版本。其链接的导出笔记本会下载 `smartywu/big-lama`，应用 `Carve-Photos/lama` 的 Fourier 导出改动，并使用 `torch.onnx.export`。

这些证据足以支持固定版本、校验哈希的研究集成，但还不是完整可复现的转换链：笔记本克隆导出器分支时没有固定 Git 版本，也没有固定源 checkpoint 的 SHA-256。模型仓库通过模型卡元数据声明 Apache-2.0，而 Places2 官方下载条款将训练图片限制为非商业研究和教育用途。模型记录和安装提示必须持续展示这些限制。

`lama.onnx` 不属于 M2 产物。其模型卡将其标为不推荐版本、使用 opset 18，并报告性能较低。

## 6. 模型安装与缓存

图片处理永远不得隐式下载模型。

无界面 CLI 将提供等价于以下形式的命令：

```text
wrl model install lama-onnx-fp32 --accept-model-terms [--cache-dir DIR]
wrl model status lama-onnx-fp32 [--cache-dir DIR] [--json]
```

安装规则：

- 展示准确来源、声明许可证、数据集限制提示、大小和 SHA-256；
- 非交互使用必须显式接受条款；
- 从产物提交下载，不使用未固定的 `main` URL；
- 先写入缓存目录内的临时文件；
- 下载时或紧接下载后计算 SHA-256；
- 只有大小与哈希都匹配时才原子发布最终缓存文件；
- 在安全情况下删除无效临时产物；
- 不得把文件名或下载成功视为完整性校验；
- 默认永远不把权重写入仓库；
- 已有验证产物时，离线处理必须可以成功；
- 缺少产物时返回可操作错误，且不得启动下载。

模型存储拥有缓存路径与描述符。用户提供的路径只有在内容匹配已审查大小和 SHA-256 时才能使用。任意描述符支持推迟到后续阶段。
在 AutoDL 上，参考缓存位于 Git 工作区外的 `/root/autodl-tmp/wrl-models`；其他主机使用等价的用户控制缓存。

首个本地实现切片只提供一个 `lama-onnx-fp32` 描述符，以及满足以下边界的无界面存储层：

- 缓存根目录依次采用适配器传入路径、`WRL_MODEL_CACHE`、平台用户缓存；
- 最终路径为 `<缓存根目录>/lama-onnx-fp32/lama_fp32.onnx`；
- 检查操作只读，永远不下载；
- 安装要求接受值必须是布尔值 `true`；
- 已验证的最终文件直接复用，不启动传输；
- 无效最终文件保持不变，除非新下载的临时文件同时通过两项校验并完成原子发布；
- 下载器可注入，因此默认测试保持离线。

此切片尚未提供上述 CLI 命令，不安装 ONNX Runtime，不创建模型会话，也不把 LaMa 接入图片流水线。只有后续切片形成最小推理闭环后，才开始 AutoDL 真实模型验收。

## 7. 运行时依赖与 provider

ONNX Runtime 保持可选，并采用惰性导入。

- CPU 使用 `lama-onnx-cpu` 可选依赖组；
- CUDA 使用 `lama-onnx-cuda` 可选依赖组；
- 同一环境中的 CPU 与 CUDA 组互斥；
- 两组都不安装时，全部 OpenCV 命令仍可运行；
- `cpu` 映射到 `CPUExecutionProvider`；
- `cuda` 在创建会话前必须确认存在 `CUDAExecutionProvider`；
- CUDA 会话可以在 CUDA 后列出 CPU 以处理不支持的节点，但 CUDA provider 缺失时必须报错，不得静默改为全 CPU；
- M2 默认使用 `cpu`；自动 provider 选择不属于初始契约；
- 规范化结果同时记录请求和实际 provider。

会话所有者必须：

- 创建会话前验证一次产物；
- 验证模型输入输出名称、类型与形状；
- 使用产物 SHA-256、provider、设备和相关 provider 选项作为会话键；
- 为缓存提供显式的进程级所有者和有界生命周期；
- 不使用导入时单例或无界全局可变缓存；
- 把 provider 初始化与内存失败转换为稳定领域错误。

第二个本地实现切片在两个冲突 extra 中固定 ONNX Runtime 1.26.0。`lama-onnx-cpu` 选择 `onnxruntime`；`lama-onnx-cuda` 在 Linux 或 Windows 上选择 `onnxruntime-gpu`。1.26 属于官方 CUDA 12.8 / cuDNN 9 GPU 版本线。升级到 1.27 引入的 CUDA 13 默认构建前，必须重新审查主机兼容性。

此切片还提供惰性的 `LamaOnnxSessionOwner`。它先校验模型产物，再导入 `onnxruntime`；要求请求的 provider 已注册且位于创建后 Session 的第一位；校验已审查的输入输出元数据；最多保留一个 Session，并在关闭时释放 owner 持有的引用。CPU 与 CUDA 使用同一图契约。默认环境不安装任何运行时，全部默认测试使用注入的假模块与假 Session。

owner 当前尚不执行输入数组。裁剪变换、张量值、`session.run`、输出校验、应用流水线接入和真实模型测试属于后续切片。

## 8. 局部裁剪契约

给定原始图片和最终细化掩膜：

1. 空掩膜绕过裁剪规划与推理，返回未改变的副本。
2. 计算包含所有选中掩膜像素的最小半开边界框。
3. 向四周扩展 `crop_padding` 像素。初始默认值为 64，且必须是非负整数。
4. 把扩展区域转换为以扩展框为中心的正方形上下文窗口，边长取扩展区域较大维度。
5. 正方形超出图片时使用反射 padding 合成上下文；只有一个像素的退化轴使用边缘复制。
6. 各向同性缩放正方形到 `512 × 512`。RGB 使用文档化的高质量插值；掩膜始终使用最近邻插值并重新二值化。
7. 以 batch size 1 运行推理。
8. 逆向应用缩放与 padding 变换，得到与原始裁剪尺寸一致的候选结果。
9. 只在原始分辨率最终掩膜为真的位置回贴候选结果。

该变换不会让宽高使用不同缩放比例。它必须记录源边界框、正方形窗口、padding、比例和警告，使逆向映射可以被测试。

上下文边长超过 512 时会缩小输入，并在结果中加入 `crop_downscaled` 警告。全图掩膜合法，但需要警告且质量可能较差。切片和重叠窗口融合推迟到测量结果证明有必要之后。

## 9. 预期张量契约

加载器必须在推理前验证准确产物：

| 张量 | 名称 | 类型 | 形状 | 数值范围 |
|---|---|---|---|---|
| 图片输入 | `image` | `float32` | `1 × 3 × 512 × 512` | RGB 归一化到 `[0, 1]` |
| 掩膜输入 | `mask` | `float32` | `1 × 1 × 512 × 512` | 二值 `0` 或 `1`；`1` 表示待补区域 |
| 输出 | `output` | `float32` | `1 × 3 × 512 × 512` | 预期 `[0, 255]` |

尽管导出声明了动态 batch 轴，M2 只提交 batch size 1。空间尺寸固定。输出需要检查有限值、裁剪到 `[0, 255]`，通过一种文档化的舍入方式转换为 `uint8`。

任何名称、类型、维度数或空间形状不匹配，都必须在处理用户媒体前以 `model_contract_mismatch` 失败。

## 10. CLI 扩展

单图命令扩展现有形式：

```text
wrl image remove INPUT OUTPUT (--box X,Y,W,H | --mask MASK)
    --method lama
    [--provider cpu|cuda]
    [--crop-padding PIXELS]
    [--model-dir DIR]
    [现有掩膜、输出、覆盖和 JSON 选项]
```

规则：

- LaMa 的 `--provider` 默认为 `cpu`；
- `--crop-padding` 默认为 64，且只用于 LaMa；
- OpenCV `--radius` 不影响 LaMa，用户显式传入不兼容选项时必须失败，不能静默忽略；
- `--dilate` 继续作为所有补全器共享的掩膜细化选项；
- JSON 结果包含后端 ID、产物 SHA-256、裁剪变换、请求/实际 provider、耗时、警告和稳定错误；
- 启用 JSON 时，人类诊断继续写入标准错误。

CLI 继续调用公开单图服务，绝不直接创建 ONNX Runtime 会话。

## 11. 稳定错误契约

M2 至少增加以下错误码：

| 错误码 | 含义 |
|---|---|
| `model_not_installed` | 选定缓存中不存在已审查产物 |
| `model_integrity_failed` | 大小或 SHA-256 不匹配描述符 |
| `model_terms_not_accepted` | 安装请求没有显式接受条款 |
| `runtime_not_installed` | 选定的可选 ONNX Runtime 包不可用 |
| `provider_unavailable` | 请求的 execution provider 未注册 |
| `model_contract_mismatch` | 模型元数据与已审查张量契约不同 |
| `session_creation_failed` | ONNX Runtime 无法创建请求的会话 |
| `inference_failed` | provider 在运行合法请求时失败 |
| `insufficient_memory` | 出现已分类的主机或设备内存不足 |
| `crop_transform_failed` | 裁剪或逆向映射无法保持契约 |

错误需要为调试保留原始异常，提供可操作的公开信息，并且不得留下最终输出或不完整模型文件。

## 12. M2 引入的 B2 行为

M2 开始实现 B2，但不复制单图流水线：

- 清单可以选择 `method: "lama"`、`provider` 和 `crop_padding`；
- 规划阶段在昂贵工作之前检查模型描述符与 provider 可用性；
- 成功项记录输入、掩膜、规范化配置、软件、模型产物和输出指纹；
- 只有 [BATCH_PROCESSING.md](../BATCH_PROCESSING.zh-CN.md) 中的全部身份都匹配时，恢复操作才能复用输出；
- 模型 SHA-256、provider、裁剪变换、掩膜或应用版本变化会把条目标记为 stale；
- GPU 默认每个设备只运行一个推理条目；
- CPU 并发受显式 worker 与内存预算限制；
- 只有在线程安全策略有文档时才能复用同一个已验证会话；
- 队列深度有界，调度器不得静默降低裁剪质量；
- 确定性的模型、完整性、契约和校验失败永不自动重试。

批量执行不下载模型。安装是独立的预检操作。

## 13. 测试矩阵

### 默认离线测试

- 空、单像素、接触边缘、非正方形和全图掩膜；
- 半开边界框推导与可配置 padding；
- 正方形窗口构建和反射/边缘 padding；
- 正向与逆向坐标映射；
- RGB 插值与掩膜最近邻插值；
- 模型空间变换后的重新二值化；
- 掩膜外像素完全不变以及 Alpha 逐字节保持；
- 图片与掩膜输入不可变；
- 假会话输入归一化、名称、dtype 与形状；
- 非有限值与越界输出处理；
- 缺少运行时、provider、模型与完整性失败；
- 使用本地假传输测试原子模型安装；
- 缓存键、会话所有权与有界复用；
- CLI 选项兼容性与失败非零退出码；
- B2 指纹、stale 分类、恢复与 provider 调度。

默认测试使用假实现或很小的合成 fixture。除非选择可选测试环境，否则它们不导入重型运行时、不访问网络，也不下载模型。

### 可选真实产物测试

显式标记的测试套件必须：

- 使用固定版本且已校验哈希的产物；
- 按预期张量契约验证 ONNX 元数据；
- 在合成 RGB 图片与二值掩膜上运行 CPU 推理；
- 验证有限的 `uint8` 输出和精确的掩膜外回贴；
- 仅在可选环境声明兼容硬件与运行时后运行 CUDA；
- 报告实际使用的运行时和 provider 版本。

`model` pytest marker 选择固定真实产物测试；`gpu` marker 进一步要求兼容 GPU provider。只有加入对应实现切片时才注册这些 marker，它们永远不属于默认离线套件。

参考运行发生在 AutoDL，但测试不得导入 AutoDL API，也不得依赖适配器传入缓存路径之外的 AutoDL 文件系统。

M2 验收前，固定产物必须完成一次真实 CPU 冒烟测试。

## 14. 基准与评审证据

使用完全一致的解码输入与最终掩膜比较 OpenCV Telea、OpenCV Navier-Stokes 和 LaMa。

M2 基准记录：

- 合成或已授权来源及干净参考图的出处；
- 掩膜类别和选中像素数；
- 裁剪大小、缩放比例和缩小警告；
- 后端、产物 SHA-256、运行时版本、provider 和硬件；
- 单独报告预热后的墙钟耗时；
- 峰值 RAM，以及适用时的 VRAM；
- 相对干净合成参考图的掩膜区域误差；
- 编码前掩膜外精确像素变化数；
- 失败项和排除项。

报告分布和有代表性的失败，而不只报告平均值或筛选后的成功案例。基准可能显示 LaMa 在部分纹理区域更好、在其他区域更差；“普遍优于传统算法”不是 M2 退出门槛。

## 15. 验收清单

只有满足以下条件，M2 才算完成：

- [ ] 固定产物与条件使用限制持续记录在 `MODEL_LICENSES.md`；
- [ ] 模型安装由用户明确触发、原子化、固定提交并校验 SHA-256；
- [ ] 未安装任何模型可选依赖的环境仍可运行 OpenCV 命令；
- [ ] CPU 与 CUDA 请求具有显式 provider 行为，且不静默回退；
- [ ] 局部裁剪和逆向变换覆盖边缘与全图情况；
- [ ] 真实产物通过张量契约校验与 CPU 冒烟测试；
- [ ] 最终掩膜外像素和 Alpha 保持 M1 不变量；
- [ ] 失败不会发布不完整输出或未验证模型文件；
- [ ] B2 恢复包含准确模型与变换指纹；
- [ ] provider 感知并发与内存限制具有测试；
- [ ] OpenCV/LaMa 对比证据记录质量和资源限制；
- [ ] AutoDL 或等价主机按照 `MODEL_EXECUTION.zh-CN.md` 生成经过评审的环境记录；
- [ ] 受影响文档的两个语言版本同步更新；
- [ ] 除非后续许可证审查明确批准，否则继续禁止再分发模型。

## 16. 建议实现切片

1. 模型描述符、缓存路径、原子安装器与完整性测试；
2. 可选 ONNX Runtime 依赖组和 provider 诊断；
3. 裁剪变换数据契约与纯单元测试；
4. 带假会话边界的 LaMa ONNX 适配器；
5. 单图服务与 CLI 扩展；
6. 可选固定产物 CPU 冒烟测试；
7. B2 指纹、已验证恢复与有界 provider 调度；
8. 基准、验收证据与文档复核。

每个切片都必须可以独立评审，并遵循仓库提交信息规范。
